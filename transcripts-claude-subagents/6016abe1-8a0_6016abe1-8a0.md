## 2. Formal model and invariants

### 2.1 Zero-one reduction

The search starts from all \(2^n\) binary vectors (`PROVER` lines 24–30, 140–142). This relies on the zero-one principle. The arena states and sketches that theorem at `README` lines 90–104.

This is a mathematical theorem rather than something proved by the submitted computation. The arena’s finite cross-check against integer permutations (`README` lines 138–141 and 457–458) is regression evidence for small \(n\), not a general proof of the principle.

### 2.2 Set-state abstraction

The program stores only the set of reachable vectors, discarding which original input produced which vector. This is sound:

1. Every comparator suffix is a deterministic function on the current vector.
2. If it sorts every vector in the reachable set, it sorts every original input reaching that set.
3. Multiplicity and source identity therefore do not affect suffix feasibility.

The exact set-image operation at `PROVER` lines 115–116 preserves this abstraction without approximation.

### 2.3 Layer normal form

A parallel layer must be a matching because two comparators sharing a wire cannot execute simultaneously. Conversely, disjoint comparators commute. The arena’s depth metric is the critical-path/ASAP layer count (`README` lines 268–284), so any submitted sequence of depth \(d\) can be represented as \(d\) ordered matching layers, subject to the comparator-orientation issue below.

Partial matchings are included (`PROVER` lines 70–91; `FINDING` lines 38–44). This is complete; the search does not assume without proof that every layer can be maximal.

### 2.4 Commutativity

Disjoint comparators operate on independent bit positions, so their composition is order-independent. This follows directly from the layer invariant.

The self-test is weaker than the prose suggests. `check_layer_commutes` makes only one random shuffle per layer (`PROVER` lines 175–190), without a fixed seed. For \(n=5\), two-comparator layers may be shuffled back into their original order and therefore not test the alternate order. The claim that commutation was “verified explicitly” for all 25 layers (`FINDING` lines 54–58) should be understood as a randomized sanity check, not exhaustive permutation testing.

This does not threaten correctness because disjointness itself supplies a deterministic proof. A deterministic reverse-order test would nevertheless be preferable.

## 3. Subset-dominance pruning

The implementation discards \(B\) when it has retained a state \(A\subseteq B\) at the same level (`PROVER` lines 119–134, 165–168). The prose gives only:

> any network sorting \(B\) sorts \(A\)

(`PROVER` lines 47–48 and 120–121; `FINDING` lines 46–48).

That sentence is directionally right but omits an invariant needed because the implementation recognizes success by **equality** with the target, not merely by inclusion in it.

A complete proof is:

1. Every reachable state contains at least one vector of each Hamming weight \(0,\ldots,n\), because the initial state does and comparators preserve weight.
2. Every suffix map \(F\) is inclusion-preserving:
   \[
   A\subseteq B\implies F(A)\subseteq F(B).
   \]
3. If \(F(B)=T\), where \(T\) is the sorted target, then \(F(A)\subseteq T\).
4. Since \(F(A)\) still contains a vector of every weight and \(T\) contains exactly one vector of each weight, necessarily \(F(A)=T\).

Therefore a retained subset is a valid replacement for a discarded superset when asking whether some suffix reaches the exact target.

The implementation of `prune_subsets` is consistent with this argument. Sorting by cardinality and comparing only with retained smaller states is sufficient: if a discarded state would dominate a later candidate, a retained subset of that discarded state also dominates it.

Other pruning/deduplication steps are also sound under the set abstraction:

- skipping `s2 == st` (`PROVER` lines 155–157) is safe because the layer is an identity at the state-set level;
- skipping an exact state already in `seen` (`PROVER` lines 147, 161–162) is safe because an earlier occurrence leaves at least as much remaining depth;
- applying a layer to a representative subset produces a subset of the result obtained from the dominated state.

Thus subset pruning does not appear to inflate the depth result. The proof should, however, state the weight-coverage invariant explicitly rather than rely on the one-line argument.

## 4. Principal completeness gap: comparator orientation

This is the main qualification.

The arena’s comparator model permits both orientations:

- `[i,j]` puts the minimum on \(i\), maximum on \(j\) (`README` lines 41–42);
- `i > j` is explicitly allowed (`README` line 170).

The arena’s original depth prover therefore searches “every orientation of every matching” (`REFERENCE` lines 78–83). Its `code-proven` status is defined in those terms (`REFERENCE` line 32).

The submitted prover does not do this:

- `itertools.combinations(range(n),2)` always gives \(i<j\) (`PROVER` line 76);
- `layer_table` always puts 0/minimum on \(i\) and 1/maximum on \(j\) (`PROVER` lines 103–107);
- the layer counts—75 for \(n=6\), for example—are counts of standard matchings, whereas the all-orientations count for \(n=6\) is 330.

Consequently, the program proves the lower bounds directly only for networks in which every comparator places the minimum on the lower-numbered wire.

To extend this to the arena’s declared network model, one needs the following theorem:

> Every ascending sorting network of depth \(d\) using arbitrarily oriented comparators can be transformed into an ascending sorting network of depth at most \(d\) in which every comparator puts the minimum on the lower-numbered wire.

This is the generalized-network “untangling” or standardization obligation. It is plausible and classical, but it is neither stated nor proved in the agent-019 artifacts. The issue is especially conspicuous because `REFERENCE` lines 127–143 deliberately refuse an assumption-free status upgrade when a lower-bound search depends on a standardization theorem.

The finding carefully declines a maximal-layer restriction because its reduction theorem was not verified (`FINDING` lines 42–44), but silently makes the comparator-orientation restriction.

My all-orientations search through \(n=5\) is useful corroboration, but it does not discharge the obligation for \(n=6,7\).

### Consequence for arena status

The existing reference still labels \(D(6)\) and \(D(7)\) as `reported-opt` (`REFERENCE` lines 54–55). The finding proposes changing them to `code-proven` (`FINDING` lines 94–107), but that change would not satisfy the current definition of `code-proven`, which expressly uses all orientations and claims no reliance on unchecked theorems.

An upgrade is justified only if either:

1. the arena adopts the standard min-to-lower comparator convention as its model; or
2. the standardization/untangling theorem is supplied and accepted as part of the proof contract; or
3. the computation is rerun over all comparator orientations.

## 5. BFS and minimum-depth claim

Subject to orientation completeness, the BFS argument is sound.

`minimum_depth`:

- starts at the complete binary input state;
- applies every generated layer;
- processes states in increasing layer count;
- tests the target before advancing to the next level (`PROVER` lines 137–172).

With the subset-representative induction above, if a target is absent through depth \(d\), no network in the searched model has depth at most \(d\). Finding the target first at depth \(d+1\) establishes the matching upper bound internally.

No heuristic or symmetry quotient is present. The claim of no symmetry reduction (`PROVER` lines 40–45; `FINDING` lines 48–52) is confirmed by the source.

The search does not retain predecessor pointers, so it cannot emit an independently checkable witness network. This is not fatal for the lower-bound half, but it makes the reported exact \(D(n)\) less auditable than necessary.

## 6. Proof-contract defects

### 6.1 The self-test does not gate normal proof output

The prose repeatedly states that the self-test “refuses to report anything” or “gates all output” (`PROVER` lines 50–55; `FINDING` lines 116–121).

That is false as implemented.

The self-test runs only when `--selftest` is explicitly supplied (`PROVER` lines 228–241). Normal `--n` and `--rule-out` execution proceeds directly at lines 243–266 without calling it or checking a persisted validation result.

Thus the self-test is an optional regression command, not a fail-closed proof gate.

### 6.2 Zero-depth reporting bug

The `--rule-out` conclusion uses `if D` instead of `if D is not None` (`PROVER` lines 251–257). For \(n=1\), where \(D=0\), the output is internally contradictory:

- `"network_exists": true`;
- `"conclusion": "PROVEN: no sorting network of depth 0 exists for n=1..."`.

This does not affect the \(n=4,\ldots,7\) claims, whose found depths are positive, but demonstrates that the proof-reporting contract is not uniformly reliable.

### 6.3 Domain and cap behavior

- `--n` and `--rule-out` are not validated for nonnegative, meaningful domains (`PROVER` lines 218–226, 243–249).
- Without `--rule-out`, the search silently defaults to `cap = 2*n` (`PROVER` line 139). A `None` result then means only “not found within that cap,” not a global nonexistence result.
- Normal proof commands return exit status zero whether they establish a lower bound or find a network; automation must parse the JSON.
- `"exhaustive": true` is printed without recording the orientation restriction or theorem dependency (`PROVER` lines 252–261).

### 6.4 Inconsistent self-test scope

The finding and data describe validation through \(n=7\) (`FINDING` lines 6, 29–31; `DATA` line 5), but:

- the source documentation says \(D(1..8)\) (`PROVER` lines 52–54);
- `--max-n` defaults to 8 (`PROVER` line 222);
- the reproduction command omits `--max-n 7` (`FINDING` line 127).

Therefore the published reproduction command attempts the unreported \(n=8\) calculation rather than reproducing exactly the archived \(n\le7\) evidence.

### 6.5 Frontier profile semantics

When a target is encountered, the program appends a hardcoded `1` and returns immediately (`PROVER` lines 158–160). Therefore the terminal `1` in

\[
[1,105,2044,7644,714,39,1]
\]

(`FINDING` lines 77–84; `DATA` lines 31–38) denotes “one target encountered,” not the size of a completely generated final frontier. Calling the whole list a frontier profile is slightly imprecise.

## 7. Reproducibility evidence

### Present and useful

- Stdlib-only source is provided.
- The layer counts, frontier profile, and timings are recorded (`DATA` lines 1–41).
- Concrete reproduction commands are listed (`FINDING` lines 124–132).
- Known expected depths are embedded (`PROVER` line 67).
- The reported \(n\le7\) results were reproducible in this review.
- The extant arena records valid upper-bound networks for \(n=6,7\) in its captured scoring output (`README` lines 477–480), although those submission files were not among the artifacts requested for direct review.

### Missing or weak

- The JSON is a summary, not raw command output or a proof certificate.
- There is no source hash, Python version, machine description, exact command line, timestamped stdout/stderr, or exit status in the data file.
- No predecessor network is emitted when a target is found.
- No independently checkable certificate covers all successors and subset-dominance deletions.
- The self-test compares against hardcoded expected constants; matching them is regression evidence, not independent proof of the lower bounds.
- The \(n=7\) lower bound has not been reproduced here by an independent algorithm or by the same algorithm with pruning disabled.
- The headline “20x cheaper” (`FINDING` line 4) is not a defined aggregate: the reported individual speed ratios are 33× and 5× (`FINDING` lines 65–68).

## 8. Claim classification

### Mechanically supported

- The code exhaustively explores all nonempty partial matchings with standard min-to-lower comparators.
- Layer generation is unique and disjoint.
- The transition and target encodings are correct.
- No symmetry reduction is used.
- The stated standard-layer counts for \(n=4,\ldots,7\) are correct.
- The submitted implementation reproduces \(D(4)=3,D(5)=5,D(6)=5,D(7)=6\) in its searched model.
- The \(n=4,5\) answers survive an independent all-orientations search.
- The \(n=4,5\) exact depths and \(n=6\) lower bound survive disabling subset pruning.
- Subset dominance is sound once the omitted weight-coverage invariant is added.

### Requiring an explicit theorem or convention

- Extending the \(n=6,7\) lower bounds from min-to-lower comparators to the arena’s arbitrary comparator orientations.
- Treating the results as meeting the existing assumption-free `code-proven` contract.
- Extending binary correctness to arbitrary totally ordered inputs via the zero-one principle, although that theorem is at least stated and sketched in the arena.

### Unsupported as written

- The statement that self-testing gates or precedes all proof output.
- The claim that the current computation already meets the arena’s “every orientation” definition of `code-proven`.
- Uniform correctness of the `--rule-out` reporting contract, due to the \(D=0\) bug.
- Treating the archived JSON as a standalone independently checkable computational proof.

## 9. Minimal independent-check plan

1. **Resolve comparator orientation.** Either provide a formal depth-preserving untangling lemma, with its output-order argument, or rerun the lower-bound search over every directed matching: 330 layers for \(n=6\) and 1,302 for \(n=7\).

2. **Independently certify \(n=7,d=5\).** Encode existence of a directed depth-5 network as SAT and obtain an UNSAT certificate, preferably DRAT/LRAT checked by a separate proof checker. This avoids relying on the same Python antichain implementation.

3. **Export checkable artifacts.** Emit:
   - explicit depth-\(D(n)\) witness networks;
   - per-level state counts and hashes;
   - for every discarded state, a retained subset witness;
   - source hash, command line, interpreter version, exit status, and raw log.

4. **Repair the contract.** Make normal proof execution run the self-test fail-closed, use `D is not None`, validate arguments, and report the exact searched comparator model in JSON.

## Final verdict

**CONFIRMED WITH EXPLICIT ASSUMPTIONS**

The numerical lower bounds are supported for standard min-to-lower comparator networks, and the BFS/subsumption logic is sound after making the Hamming-weight invariant explicit. Applying those bounds to the arena’s broader directed-comparator model—and upgrading \(D(6),D(7)\) to its current assumption-free `code-proven` status—requires an explicit depth-preserving standardization theorem or an all-orientations computation.
