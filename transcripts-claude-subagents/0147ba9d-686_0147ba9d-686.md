## Mathematical model and assumptions

### 1. Zero-one reduction

The search assumes the zero-one principle: sorting all \(2^n\) binary inputs is equivalent to sorting every input over a totally ordered domain. This is stated in the prover at lines 27–35 and given a valid proof sketch in `README.md` lines 90–104.

This is a standard and adequate assumption.

### 2. Reachable-output-set abstraction

A prefix is represented only by the set of its binary outputs, not by input/output multiplicities or histories (`frozenset`, prover lines 80–103).

This quotient is exact for the property being decided:

- every suffix is a deterministic function of its current vector;
- two prefixes with the same output set therefore have identical possible behavior under every suffix;
- multiplicity is irrelevant to universal sorting.

### 3. Target equality

The target is the set of \(n+1\) ascending binary vectors, one per Hamming weight (lines 85–87). Comparators preserve Hamming weight, and the initial state contains every weight. Therefore a state is sorted iff it equals this target; checking equality rather than mere containment is sound.

### 4. BFS minimality

Without optional symmetry or subsumption, `minimum_size` is ordinary breadth-first search over output states:

- the initial state is depth zero: lines 253–261;
- every nontrivial standard comparator successor is generated: lines 262–275;
- a target reached while expanding level \(d-1\) has minimum depth \(d\): lines 270–272.

Thus, for the implemented comparator universe, exhausting levels through 11 and first reaching the target at 12 establishes the exact minimum.

### 5. Standard-comparator restriction

This is the principal omitted assumption.

The arena allows every oriented comparator `(i,j)` with \(i\ne j\), including `i > j` (`README.md` lines 165–170). Agent-017’s unrestricted tiny search explicitly ranges over all ordered pairs (`REFERENCE.md` lines 78–83).

The new prover instead uses:

```python
itertools.combinations(range(n), 2)
```

so it searches only \(i<j\) comparators (prover lines 190–196).

To transfer its lower bound to the arena’s larger oriented-comparator universe, one needs the classical **standardization or untangling theorem**:

> Every oriented comparator network that sorts into the natural ascending wire order can be transformed, without increasing its number of comparators, into a network whose comparators all put the minimum on the lower-indexed wire.

Agent-017 explicitly identifies this theorem as the reason its earlier \(n=6\) standard-only result was left `reported-opt` (`REFERENCE.md` lines 125–143). Agent-019 does not acknowledge the same dependency when claiming an assumption-free upgrade.

The theorem is standard and true, so the result transfers if it is admitted or proved. But the published statement “neither taken on trust” at finding lines 46–48 and the suggestion to upgrade to assumption-free `code-proven` at lines 146–156 are too strong as written.

### 6. Permutation-subsumption theorem

The default configuration discards \(B\) when a permutation maps a smaller state \(A\) into a subset of \(B\) (prover lines 211–250).

This is standard sorting-network subsumption, but its soundness is not established by the one-sentence argument in the source. It relies on a theorem of the form:

> If same-depth reachable states satisfy \(\pi(A)\subseteq B\), every sorting completion through \(B\) implies a no-longer sorting network represented through \(A\), after relabeling and untangling.

The necessary untangling step matters because the sorted target is not permutation invariant—the source correctly recognizes this for naive canonicalization at lines 173–179.

This missing proof does **not** invalidate the \(n=6\) conclusion because the successful `--no-subsumption` run bypasses permutation subsumption entirely. It does mean the fast/default path is conditional on an unstated dominance theorem.

## Documentation and implementation defects

### A. The module-level method description is materially stale

The opening description says the implementation uses iterative-deepening DFS, an unresolved-pair lower bound, and symmetry canonicalization, and that all three preserve completeness (prover lines 23–52).

The actual implementation is BFS; the lower bound raises `NotImplementedError`; and symmetry is known to be unsound (lines 106–131 and 162–187). The later class documentation corrects much of this, but line 186 still says “Both are sound” immediately after describing symmetry as unsound.

A formal-proof artifact should not contain mutually incompatible proof descriptions.

### B. Unsafe mode does not fail closed

The CLI advertises `--symmetry` as unsound (lines 328–329) but still permits it with `--rule-out`, labels the result `"exhaustive": true`, and may print a false `PROVEN` conclusion. This is an implementation-level proof-integrity defect, even though it does not affect the default runs.

### C. The self-test is not an enforced gate

The prose says the prover “self-validates” and that disagreement voids all output (prover lines 50–59; finding lines 140–152). In the implementation, however:

- self-test runs only in the separate `--selftest` branch: lines 335–350;
- `--rule-out` and `--prove` do not call it: lines 355–395;
- `--rule-out` nevertheless emits the static string `"prover_validated_against": "S(1..6)=..."` at line 373.

Thus a proof run is not automatically coupled to a successful self-test. The provided historical evidence may include such a run, but the program does not enforce the claimed gate.

### D. “Two independent configurations” is overstated

The pruned and unpruned runs share:

- the bit encoding;
- comparator transition;
- target construction;
- \(i<j\) restriction;
- BFS logic;
- target test;
- exact-state deduplication.

They are useful differential configurations, and the unpruned one protects against an unsound subsumption rule. They are not independent proof implementations and cannot detect shared transition, target, orientation, or standardization errors. Finding lines 122–126 and JSON lines 38–44 should use “two configurations,” not imply fully independent verification.
