## 1. Formal reconstruction of the valid proof core

### Reachable-set invariant

For a comparator prefix \(P\), define

\[
R(P)=\{P(x):x\in\{0,1\}^n\}.
\]

The implementation represents this exactly as a `frozenset` of bit vectors (`prover.py:80-103`). For a comparator \(c\),

\[
R(Pc)=\{c(v):v\in R(P)\},
\]

which is exactly what `apply_comparator` computes (`prover.py:94-103`). Consequently, multiplicities and the identity of the original input can be forgotten: every future suffix acts only on the current vector, so the reachable set is a sufficient Markov state.

### Target invariant

`sorted_vectors` constructs the \(n+1\) ascending binary vectors, one for each Hamming weight (`prover.py:85-87`). Every comparator preserves Hamming weight. Because the initial set contains inputs of every weight, every reachable state contains at least one vector of every weight. Therefore:

\[
R(P)\subseteq T \quad\Longleftrightarrow\quad R(P)=T.
\]

Thus the equality check at `prover.py:270` is sound, although the weight-preservation argument is not stated there.

### Zero-one reduction

The binary restriction relies on the zero-one principle. Unlike the standardization issue below, this theorem is accompanied by an adequate threshold-map proof sketch in `README.md:90-105`.

### BFS completeness for standard comparators

The actual search is breadth-first search (`prover.py:253-282`), not the iterative-deepening DFS described in the obsolete module header.

For the standard-comparator domain:

- All \(\binom n2\) pairs \(i<j\) are enumerated (`prover.py:193`).
- A transition that leaves a state unchanged is skipped (`prover.py:267-269`). This is sound because the no-op comparator can be deleted.
- Exact duplicate states are suppressed globally (`prover.py:260,273-280`). This is sound because an earlier occurrence of the same state has at least as much remaining comparator budget.
- At depth \(d\), every nonredundant standard-comparator prefix of minimum state-reaching length \(d\) is therefore represented, unless optional subsumption is used.

With `use_subsumption=False` and `use_symmetry=False`, absence of the target through depth 11 is a complete proof for the standard-comparator search space.

## 3. Material findings

### F1 — The search silently excludes comparator orientations allowed by the arena

**Severity: high; requires an explicit theorem.**

The arena defines `[i,j]` as min-to-\(i\), max-to-\(j\), expressly allowing \(i>j\) (`README.md:41-46,165-171`). Its original unrestricted proof search therefore enumerated every ordered pair (`REFERENCE.md:71-83`).

The new prover instead enumerates only:

```python
itertools.combinations(range(n), 2)
```

at `prover.py:193`, while `apply_comparator` assumes \(i<j\) (`prover.py:94-101`). The finding's method description does not disclose this restriction (`finding.md:50-62,128-139`).

This is precisely the assumption discussed in `REFERENCE.md:125-143`: its earlier \(n=6\) standard-only result was deliberately left as `reported-opt` because the lower bound depended on the classical standardization theorem.

The missing bridge can be supplied by the following explicit lemma:

> **Untangling/standardization lemma.** Any sorting network made from directed comparators can be transformed, without increasing comparator count, into a sorting network in which every comparator has \(i<j\) and places the minimum on \(i\).

Proof sketch: represent each reverse comparator as a standard comparator followed by a wire swap; commute the swaps through later gates, relabelling those gates, until only a final wire permutation remains. The resulting standard-comparator prefix fixes every already-sorted input. Since the original generalized network sorts, the final permutation must fix every sorted input and hence every wire, so it is the identity.

With this lemma, the \(i<j\) restriction is without loss of generality. Without it, the code proves only the standard-comparator version of the claim.

### F2 — The default subsumption reduction needs the same untangling lemma

**Severity: medium for the reported result, because an unpruned run exists.**

The implementation discards \(B\) if some wire permutation maps a smaller state \(A\) into a subset of \(B\) (`prover.py:212-250`). The source calls this sound at `prover.py:180-187`.

Subset monotonicity alone is insufficient because the sorted target is not invariant under arbitrary wire permutations—the source itself recognizes that fact for canonicalization (`prover.py:173-180`).

The correct dominance proof is:

1. Relabel a prefix reaching \(A\), producing a generalized prefix reaching \(\pi(A)\subseteq B\).
2. Append any suffix that sorts \(B\).
3. The resulting generalized network sorts all binary inputs.
4. Apply the untangling/standardization lemma to obtain a standard network of the same size.

That theorem is not stated in the subsumption argument. Nevertheless, the published \(n=6\) conclusion does not depend on subsumption because the no-subsumption run independently gives the same result.

The statement that agreement proves the pruning itself sound is too strong (`finding.md:122-126`). An unsound pruning can happen not to remove the decisive route on a particular instance. Agreement confirms the \(n=6\) answer, not the general pruning theorem.

### F3 — A known-unsound mode can emit a false certified proof

**Severity: critical proof-tool safety defect.**

The code correctly says wire-permutation canonicalization is unsound (`prover.py:173-180`) but exposes it through `--symmetry` (`prover.py:328-329`) and passes it directly into proof-mode construction (`prover.py:355-356`).

I ran:

```text
--symmetry --n 4 --rule-out 5 --json
```

The program falsely reported:

```text
PROVEN: no sorting network of size 5 exists for n=4, so S(4) >= 6
exhaustive: true
prover_validated_against: S(1..6)=0,1,3,5,9,12
```

Yet \(S(4)=5\), including a witness in `REFERENCE.md:93-96`.

Thus `exhaustive: true` and `PROVEN` are not reliable output contracts for this executable. A proof tool should reject `--symmetry` in `--prove` and `--rule-out` modes rather than knowingly issue false certificates.

### F4 — Self-testing is not an enforced or configuration-specific gate

**Severity: high for provenance claims.**

The documentation says disagreement in self-test voids every other output (`prover.py:54-59`) and describes a “selftest gate” (`finding.md:140-152`). In fact:

- `--selftest` is a separate branch (`prover.py:335-350`).
- `--rule-out` and `--prove` do not invoke it (`prover.py:355-395`).
- `prover_validated_against` is an unconditional static string (`prover.py:362-374`).
- The self-test constructs `Prover(n)` with default options (`prover.py:296-303`), so it does not test the requested `--symmetry` or `--no-subsumption` configuration.

I confirmed that `--symmetry --selftest` passes because the symmetry flag is ignored, even though symmetry proof mode immediately gives a false \(n=4\) lower bound.

The header and finding also say the self-test reproduces \(S(1..8)\) (`prover.py:56-58`; `finding.md:72-75`), while the actual default ceiling is 6 (`prover.py:325-327`). The constants through 8 are present, but no default \(n=7,8\) validation occurs.

### F5 — The top-level method and correctness description is obsolete and false

**Severity: high documentation defect.**

The module header claims iterative-deepening DFS with:

1. memoization on `(state,budget)`;
2. an admissible unresolved-pair lower bound;
3. sound symmetry canonicalization;

and says all three preserve completeness (`prover.py:23-52`).

The actual source later says:

- the unresolved-pair bound is invalid and always raises (`prover.py:106-131`);
- symmetry canonicalization is invalid (`prover.py:173-180`);
- the implemented algorithm is BFS with optional permutation subsumption (`prover.py:163-187,253-282`).

The class documentation then compounds the contradiction by saying “Both are sound” immediately after describing symmetry as unsound (`prover.py:171-187`). A reader relying on the module-level proof argument would be relying on two reductions the implementation itself disproves.

### F6 — No-subsumption output misstates the configuration

**Severity: medium reproducibility defect.**

Even under `--no-subsumption`, JSON output says the method used “permutation-subsumption dominance pruning” because the method field is hardcoded (`prover.py:370-373`). The code does disable it correctly at `prover.py:355-356` and `222-223`, but the result record is false about the path executed.

Consequently, `data.json:6-25` is more informative than the CLI output, but it still contains no command line, source hash, Python version, or frontier digests.

### F7 — The \(n=7\) addendum has weaker evidence than the \(n=6\) result

**Severity: medium.**

The addendum claims \(S(7)=16\) and gives a detailed frontier trace (`finding.md:172-189`). The numbers are internally consistent: the listed frontier counts through depth 14 sum to 1,940,568, and the claimed node total 1,940,586 corresponds to finding the target after expanding 18 of the 24 depth-15 states.

However:

- `data.json` contains only \(S(4),S(5),S(6)\) (`data.json:27-45`);
- its validation field stops at \(S(1..6)\) (`data.json:5`);
- there is no stored \(n=7\) command, environment, frontier digest, or witness path;
- I did not complete a fresh \(n=7\) enumeration during this audit.

Thus the \(n=7\) trace is a plausible and reproducible reported execution, but it lacks the machine-readable corroboration supplied for \(n=6\).
