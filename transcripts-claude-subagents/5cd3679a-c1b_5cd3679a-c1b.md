# Formal-methods and combinatorial-search review

## Scope

I read all five listed artifacts directly and inspected the executable search implementation line by line. I also reran:

- the unpruned \(n=6\) search,
- the unpruned \(n=6\), size-\(\le 11\) exclusion,
- the default self-test through \(n=6\), and
- the intentionally unsound symmetry mode.

This review is independent of the artifact authors, but no secondary model or sub-agent was used, as requested.

## Executive assessment

The executable, with dominance pruning disabled, performs a complete breadth-first search over **standard comparators** \((i,j)\) with \(i<j\). That search reproducibly reaches the sorting target first at depth 12 and exhausts all reachable states through depth 11.

Therefore the following fact is mechanically supported:

> No 6-wire network consisting only of comparators that place the minimum on the lower-indexed wire has size at most 11, while such a network exists at size 12.

The advertised arena-wide conclusion \(S(6)=12\) additionally requires either:

1. defining “sorting network” to include only those standard comparators, or
2. invoking the classical standardization theorem that every sorting network with arbitrarily oriented comparators can be transformed, without increasing size, into one whose comparators all satisfy \(i<j\).

That theorem is not proved by the new prover. More importantly, the arena explicitly permits descending comparators and its reference document previously declined to call the same standard-only restriction “code-proven” without that theorem. Thus “neither direction taken on trust” is too strong.

## Mechanically confirmed facts

### 1. State representation and transition are correct

`sorted_vectors(n)` constructs exactly one ascending binary vector for each Hamming weight, while `all_vectors(n)` constructs all \(2^n\) inputs (`PROVER:85-91`). `apply_comparator` maps each current output pointwise through a compare-exchange operation (`PROVER:94-103`).

The required invariants are:

- every state is the image of all binary inputs under some comparator prefix;
- comparators preserve Hamming weight;
- the next state depends only on the current output set, not on the prefix that produced it;
- every reachable state contains at least one vector of every Hamming weight.

Consequently, equality with the \(n+1\)-element target is equivalent to sorting all binary inputs. Multiplicity can safely be discarded: future comparator behavior depends only on each distinct vector.

The zero-one principle needed to lift this result to arbitrary totally ordered inputs is stated and sketched correctly in `README:95-104`.

### 2. The actual search is BFS, not the DFS described at the top

The operative algorithm is breadth-first search (`PROVER:253-282`):

- the frontier initially contains the full binary state;
- every allowed comparator is applied to every frontier state;
- target detection occurs before the next level is installed;
- exact duplicate states are merged;
- previously seen states are not revisited.

Because future behavior is a function only of the state, globally discarding a state previously reached at a smaller depth is sound (`PROVER:260,273-280`). Skipping a comparator that leaves the state unchanged is also sound for minimum-size and bounded-existence questions, since it can simply be deleted (`PROVER:268-269`).

With pruning disabled, this establishes completeness over the implemented comparator alphabet.

### 3. The \(n=6\) unpruned computation reproduces exactly

My direct unpruned run returned:

```text
minimum_size = 12
nodes = 19328
level_sizes =
[1, 15, 85, 320, 1021, 2617, 4825, 5490,
 3563, 1203, 177, 14, 1]
```

This exactly matches `DATA:6-25` and `FINDING:64-70`.

The separate bounded run with `--rule-out 11 --no-subsumption` returned:

```text

nodes_expanded = 19317
```

The node-count difference is expected: the bounded run generates the depth-11 frontier and stops, whereas the minimum-size run begins expanding that frontier until it generates the target at depth 12.

This is the strongest evidence in the package because it does not use permutation-subsumption pruning.

### 4. The default pruned search agrees

The current default self-test reproduced:

\[
S(1),\ldots,S(6)=0,1,3,5,9,12.
\]

For \(n=6\), the pruned path expanded 247 states, agreeing with `FINDING:122-126`. Its runtime on this machine was 172.25 seconds rather than the reported 70–74 seconds; that is a performance variation, not a combinatorial discrepancy.

### 5. The two known bad reductions really are disabled or isolated

The unresolved-pair lower bound is correctly identified as inadmissible and its function unconditionally raises `NotImplementedError` (`PROVER:106-131`). It is not called by the current search.

The wire-permutation canonicalization is disabled by default and exposed only through `--symmetry` (`PROVER:173-180,190-209,328-331`). I reproduced the documented failure: with `--symmetry --n 4`, the program returned no minimum rather than 5. This validates the warning, though retaining an explicitly unsound mode in a proof tool remains risky.

## Assumptions and completeness gaps

### Major: the search omits descending comparators

The search alphabet is constructed using:

```python
itertools.combinations(range(n), 2)
```

so every explored comparator has \(i<j\) (`PROVER:193`).

That is narrower than the arena’s model. The arena explicitly defines `[i,j]` as min-to-\(i\), max-to-\(j\), and permits \(i>j\) (`README:41-46,165-171`). Its earlier prover deliberately enumerated all ordered pairs to avoid relying on standardization (`REFERENCE:78-83`). The same reference says a standard-only \(n=6\) result was left as `reported-opt` because its lower bound depended on an externally recalled theorem (`REFERENCE:125-143`).

Therefore:

- the unpruned execution is exhaustive over all **standard** comparator sequences;
- it is not literally exhaustive over the arena’s submitted-network space;
- extending its conclusion to that space requires the standardization theorem.

This directly qualifies the assertions that both bounds are established “by code in this swarm, neither taken on trust” (`FINDING:46-48`) and that \(n\le6\) can be upgraded without a theorem-level caveat (`FINDING:130-151`).

### The subsumption reduction is conditional on the same closure property

The default reduction discards \(B\) if some permutation \(\pi\) maps a smaller state \(A\) into \(B\), i.e. \(\pi(A)\subseteq B\) (`PROVER:212-250`).

The intended argument is valid for a comparator model closed under wire relabeling:

1. a prefix reaching \(A\) can be relabeled to reach \(\pi(A)\);
2. any continuation sorting \(B\) also sorts its subset \(\pi(A)\);
3. thus a solution through \(B\) implies a same-length solution through a relabeled \(A\)-prefix.

But arbitrary relabeling of a standard comparator can turn it into a descending comparator. The implemented standard-only search space is not directly closed under this operation. Soundness therefore again needs the standardization theorem, or a proof specialized to the standard comparator model.

This does not invalidate the \(n=6\) restricted result, because the successful `--no-subsumption` run bypasses this reduction entirely. Agreement between the two configurations is useful evidence about the pruning, but they are not truly independent implementations: they share the state encoding, target, transition, comparator restriction, BFS, and seen-state logic (`FINDING:122-126`).

## Documentation and reproducibility findings

### 1. The module-level proof description is stale and materially false

The top-level documentation says the program uses iterative-deepening DFS, memoization by `(state,budget)`, the inadmissible unresolved-pair bound, and symmetry canonicalization, and calls all three exact (`PROVER:23-52`).

The executable instead uses BFS, no heuristic, disabled symmetry, and optional subsumption. Later comments correctly explain the two unsound reductions (`PROVER:106-131,162-187`), but the contradictory opening description could cause a reviewer to validate the wrong proof argument.

### 2. The self-test coverage is overstated

The opening documentation says `--selftest` verifies \(S(1..8)\) (`PROVER:54-59`), and the finding similarly describes reproducing all eight values before trusting output (`FINDING:72-75`). In fact:

- `selftest` defaults to `max_n=6` (`PROVER:296`);
- the CLI default is also 6 (`PROVER:325-327`);
- ordinary `--rule-out` and `--prove` runs do not automatically execute or require the self-test (`PROVER:335-395`).

The self-test is valuable regression evidence, but it is not an enforced gate. Moreover, comparing the \(n=6\) result with a hard-coded expected value of 12 is consistency checking, not independent support for the newly advertised \(n=6\) proof.

### 3. Machine-readable output contains inaccurate provenance fields

For every `--rule-out` run, the output claims:

- the method used permutation-subsumption pruning, and
- the prover was validated against \(S(1..6)\),

using hard-coded strings (`PROVER:369-373`).

Those claims are printed even with `--no-subsumption`, and the rule-out invocation does not run the validation suite. I observed both inaccuracies directly. They do not change the Boolean result but weaken auditability.

### 4. The JSON is a summary, not a proof certificate

The JSON supplies the unpruned \(n=6\) frontier counts and final claims (`DATA:6-44`), but it contains no:

- source hash,
- Python version or platform,
- command-line transcript,
- timestamped stdout,
- parent pointers or witness network,
- serialized final frontier,
- independent implementation result.

Thus the lower-bound certificate is effectively “rerun this deterministic program,” rather than a compact independently checkable certificate.

### 5. The \(n=7\) addendum is not backed by the listed data artifact

The finding later claims \(S(7)=16\), with a 685-second run and detailed frontier statistics (`FINDING:172-189`). The JSON ends with \(n=6\) and contains no \(n=7\) record (`DATA:27-46`); the default self-test also stops at 6.

The \(n=7\) claim is plausible and follows the same algorithmic path, but I did not complete an independent \(n=7\) rerun here. Within the listed evidence, it remains a reported execution rather than a mechanically rechecked fact.

## Minimal independent-check plan

1. **Close the model gap.** Either add and prove a precise standardization lemma for the arena’s directed-comparator model, or independently search all ordered pairs \((i,j)\), \(i\ne j\). The theorem must state preservation of comparator count and ascending final output.

2. **Recheck \(n=6\) without optional reductions.** Run `--n 6 --rule-out 11 --no-subsumption` and `--n 6 --no-subsumption`; assert the exact frontier list and node counts above.

3. **Check the upper bound with a standalone witness.** Emit parent pointers when the target is reached, save the resulting 12-comparator network, and verify it independently over all 64 binary inputs.

4. **For the \(n=7\) addendum, archive the actual run.** Record the source hash, interpreter version, command, exit status, complete frontier counts, and raw stdout; preferably cross-check with an independently written SAT or reachable-set implementation.
