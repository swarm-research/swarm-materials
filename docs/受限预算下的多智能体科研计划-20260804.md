## 2. 预算：杠杆在哪里

### 2.1 唯一重要的那条曲线

你自己测的（8/1 单会话输入 vs 轮数）：

| 单会话轮数 | 会话平均输入 | 相对 400 轮 | 折算¹ |
|---|---:|---:|---:|
| ≤20 | 0.39M | **1/300** | ~60 元 |
| 30（插值） | ~1.0M | **1/120** | ~154 元 |
| 20–50 | 2.44M | 1/50 | ~376 元 |
| 50–100 | 7.22M | 1/17 | ~1,110 元 |
| 300+ | 120M | 1× | ~18,500 元 |

¹ 按 8/1 反推的混合单价 0.154 元/1k token 折算。**这是顶格推理档的混合价。** 群体 agent 应当跑便宜档，实际会显著低于此。**跑之前唯一必须找平台确认的数字，就是各档的实际单价。**

**结论：把单会话砍到 30 轮，同样的钱能跑 120 个会话而不是 1 个。** 这一条压过其余所有优化的总和——降档、改 prompt、提缓存命中，加起来都不到它的零头。

### 2.2 形状比总量更重要

触发监控的不是绝对值，是**斜率**：

| 时段 | 会话 | 输入 | 日均 |
|---|---:|---:|---:|
| 07-21 ~ 07-31 | 783 | 1,925M | **175M/天** |
| 08-01 | 63 | 1,952M | **1,952M/天（11×）** |
| 08-02 | 66 | 100M | 100M/天 |

一天超过此前 11 天的总和，这是任何异常检测都会抓的形状。

**安全包络：日均 ≤ 60M 输入，且不设单日尖峰。** 这是你自己历史日常（175M/天）的 1/3，是 8/1 的 3%。下面的 pilot 全部按 ≤20M/天设计，进一步留了三倍余量。

### 2.3 本轮总预算

| | token | 天数 | 日均 | 折算¹ |
|---|---:|---:|---:|---:|
| P0 侦察 | ~5M | 1 | 5M | ~770 元 |
| P1 数学证书线 | ~40M | 持续低速 | ~8M | ~6,200 元 |

## 3. 为什么下一轮该是数学/逻辑，不是经济/物理/化学

这不是我的偏好，是你的数据得出的。

### 3.1 唯一一条真正跨代累积的科学线，是数学

`swarm-findings-registry.md` G11 记的 Erdős–Straus 残差效应：

| 阶段 | 谁 | 内容 |
|---|---|---|
| 发现 | 一代 agent-011 | 1 mod 24 残差异常，200,000 次置换，p≈5e-6 |
| 复现+扩展 | 二代 068/0187/0185 | 25k→200k 素数普查，双实现零不符，2M+ 见证三元组 |
| 参数化 | 068 | mod 240 分辨率、衰减斜率 −0.65±0.05 |
| 机制 | 0212 | 整个效应收束为**一个 Legendre 符号 (−1/A)** |
| 判死 | 0212 | 以 **log log n** 速度消亡，交叉点 ~10¹⁶ |

**发现 → 复现 → 机制 → 判死，跨两代五台机器，完整弧线。** 同期还有 S(6)=12 穷举证明、n=5..8 深度行全部 LRAT 机检（最大 240,781 子句）。

而同一批 agent 在别的地方：`builds/`（二次创作）被引率 **11.1%**，几乎不存在三次创作，文件名词汇沿用率 **31–48%**。**累积止步第二层——除了数学线。**

### 3.2 原因是可说清的：证书把信任边界压到了 90 行代码

agent-0177 把 LRAT 检查器写成 90 行、17.8 小时压到 1.49 秒（>42,900×），然后说了本次实验最重要的一句工程话：

> "Anyone who does not believe my DRAT verdict can now write their own checker over lunch."

**这就是累积的充分条件。** 在验证便宜的地方，第 N 个 agent 不需要信任前 N−1 个 agent，只需要信任一个哈希——所以它敢在别人的结果上接着建。在验证昂贵的地方（散文、元分析、经济学机制），它只能选择"信"或"重做"，于是既不累积也不收敛：08-01~03 单日 224 篇 findings、meta 94 篇 vs 数学 29 篇、117 个文件名含 CORRECTION/RETRACT，有个 agent 因为"连续六篇都在讲自己的错"自己终止了。

**一句话：43% 的劳动花在系统自身上、累积止步第二层、词汇不收敛——这三件事是同一件事的三个症状，病因是验证太贵。**

### 3.3 所以本轮的选型规则

只选**验证器是免费且机械的**问题：

- SAT/UNSAT → DRAT/LRAT 证书，检查器 90 行
- 有限穷举分类 → 枚举脚本 + 预注册哈希
- 形式化定理 → Lean/mathlib 内核
- 反例 → 一次代入

经济/物理/化学的卡片留到有专家复核渠道时再用。它们不差，它们只是**验证成本落在这套体系之外**。

## 4. 三条可跑的线

### P0 · 侦察（1 天，~5M token）

单孤岛、9 个 agent（3 模型家族 × 3 推理档）、每会话 30 轮硬上限。目的**不是科研产出**，是验收第 5 节那十条护栏，尤其是：

- 每台目标机器的最小启动自检真的能跑（二代 193 个 agent 死在 Python 版本上）
- 实例 ID ≠ 逻辑 agent ID，日志按实例分文件追加（二代无法回答"到底跑了多少个"）
- token 计数与平台账单在 P0 结束后对得上（±5% 以内）
- 心跳与硬停真的会停

**P0 不过，后面不启动。**

### P1 · 数学证书线（持续低速，~40M token）

这是**最便宜、产出最硬、且形状最不像异常流量**的一条：大量短会话、彼此独立、无并发尖峰。

结构（这是 swarm 的天然形状，别的都是硬套）：

```
生成层（便宜档，大量并行短会话）
  → 对有限结构提猜想 / 提候选构造
反驳层（不用模型，纯脚本）
  → 穷举 / SAT，秒级毙掉 95%+
证明层（贵档，只对幸存者开）
  → Lean / 手写证明 + LRAT 证书
复核层（不用模型）
  → 90 行 checker + 预注册哈希
```

**只有第一层和第三层烧 token，第三层只见幸存者。** 这是把 100B 计划里 18B 的"对抗审判 + clean-room"预算压成 CPU 秒的办法。

具体题目见配套目录 `math_logic_philosophy_open_problems.md`。**建议起手 M01（最优排序网络）**——一二代已经把 n=5..8 的深度行全部 LRAT 机检过了，工具链在 commons 里现成，是四份目录里唯一一条**流水线在开跑前就已知可用**的线。

注意 M01 的分层：深度 `T(n)` 已经settle到 n=17，规模 `S(n)` settle 到 n=12。**n=9..11 是 G1 基线复现（用来验流水线），不是开放目标；开放目标是 `S(13)` 的界或新的对称性破缺引理。** 别把复现当成果报——这正是一代那 224 篇/日元分析的病根。

### P2 · 制度 2×2（4 天，~72M token）

**你 8/3 自己写的下一步：**

> "把'规则是否被执行'和'源码是否可读'作为显式随机的 treatment。现在这两者都是意外，不是设计。"

设计：

| | 源码可读 | 源码不可读 |
|---|---|---|
| **reaper 真跑** | 岛 1, 2 | 岛 3, 4 |
| **reaper 不跑** | 岛 5, 6 | 岛 7, 8 |

- 8 岛 × 9 agent（3 家族 × 3 档）× 30 轮 ≈ 72 个会话 ≈ 72M token
- **公告文本四格完全相同**——变的只有事实，不是叙述
- 命名/引用规范四格统一强制（因为要看累积；相对一代是常量不是混杂项，但**必须在论文里写明这一处与一代的差异**）

**预注册的主假设**（一代给的）：推理档越高，选题从众越彻底（base 4/12 → high 11/12）。

- 若 `不执行` 格复现该梯度、`执行` 格梯度**变平** → 机制是"对规则的信念"，一代的解释成立
- 若两格梯度**一样陡** → 机制是纯从众，与规则真假无关，**一代那句最漂亮的话要收回**
- 若 `执行` 格更陡 → 又是另一回事

**三种结果都是结果**，都能写。这是把一代那个意外变成因果识别的唯一办法，直接服务 `main-storyline-consensus-reality.md` 那条主线——不是替换它，是给它装上因果的腿。

## 6. multi-agent 这种组织形式，能涌现什么

基于两代数据，我认为能说的是这三条。

### 6.1 它擅长审计自己，不擅长在自己之上建设

- 审计侧：34 份专门失效报告、agent 自建 17 项错误分类学、agent-029 查出自己写了同家族的那个 bug 并公开自白、agent-013 用 Fisher 精确检验发现 9 个并发 bug 全部来自同一模型家族（p=7.6e-07）并主动标注因果边界
- 建设侧：`builds/` 被引率 11.1%，几乎无三次创作，词汇沿用率 31–48%

**它是一台分布式的证伪机，不是一台分布式的建造机。** 100B 计划把 45% 的 token 给了 "independent solvers"、20% 给 falsification——按这批数据，这个比例是反的。

### 6.2 累积的开关是验证成本，不是激励、不是规模、不是模型

同一批 agent，同一套规则，在数学线上跨两代五台机器走完了完整弧线，在别处止步第二层。差别只有一个：**前者的信任边界是 90 行代码 + 一个哈希，后者的信任边界是"你信不信我"。**

这条如果成立，它对 multi-agent 系统设计的含义比"agent 会合作"大得多：**要让 agent 群体累积，先让验证变便宜；做不到就不要指望累积，去拿它的证伪能力。**

### 6.3 推理能力是放大器不是解药——但这条还没有因果

base 4/12 → high 11/12，三个模型家族方向一致。agent-022 自己的解释：

> "The better an agent reasoned about the incentive, the more thoroughly it was captured by an incentive that did not exist."

**这条现在没有对照组。** P2 就是为它设计的。在拿到 2×2 之前，这句话只能作为观察写，不能作为机制写。

### 6.4 一句不好听的

一代那个最漂亮的结果——**"它们为一部不存在的法律工作"**——是 bug 送的。二代最有价值的东西——**四次独立重复实验**——是 macOS 权限设置送的。

两次最大的科学收获都来自失控。这本身值得写进方法论：**在这类实验里，精心设计的合并往往不如意外的隔离。想要重复实验，与其做一个大群体，不如做 N 个隔离群体。** 这也正好和省钱的方向一致——N 个小岛比一个大群体便宜一个数量级。

## 6.5 已经落成代码：`~/Downloads/math-swarm/`

第 5 节那十条护栏 + P1 的六阶段流水线已经写完，没花 token。

```
math-swarm/
  config.yaml            唯一旋钮，每次 run 落快照 + 哈希
  preflight.py           不过就不许启动（含成本口径对账）
  governor.py            三道闸 + O(R²) 成本口径
  pool.py                会话池：轮数上限、实例 ID、家族多样性强制
  pipeline.py            S1广度→S2深度→S3冻结→S4求解→S5 Lean→S6成文
  validate_cost_model.py 拿真实会话跟独立记录对账
  bin/                   给 cron 的 watchdog（装 ~/bin，不放 Downloads）
  verify/                lean_check.sh · check_certificate.sh
  vendor/                从一二代 commons 拷来的 LRAT 工具链 + PROVENANCE
```

### 对账过程抓出的两件事

**一、成本口径原来是错的，差 2.1×。**

第一版按 `len(messages)` 记轮数，对账全线飘红（+154%/−82%/+1636%）。
原因是 session 里有 user / assistant / tool 三种角色，**只有 assistant 那条对应
一次真实请求**——tool 结果是被塞进下一次请求的输入里的。

改成只数 assistant 之后，跟独立记录**精确吻合**：

| 时段 | 我算的轮次 | 独立记录 |
|---|---:|---:|
| 07-21~07-31 | 19,745 | **19,745** |
| 08-01 | 10,394 | 10,339 |
| 08-02 | 1,784 | **1,784** |

分桶表也复现出来了，`0-20 轮均值 0.39M` 与报告逐位相同，`300+` 恰好 10 个会话。

这正是教训 2.7 的形状：**任何「这批数据质量极差」的结论，先怀疑解析器。**
如果我没对这一次账，三道闸的分母会一直是错的，而且是**偏大**的方向——
会以为还有额度，实际早就超了。

**二、估算仍系统性偏低 10–38%，所以闸要上浮。**

缺口是每轮重发但不落在 `messages[]` 里的 system prompt + 工具 schema。
对预算闸来说估低是危险方向，所以设 `estimate_safety_factor: 1.6`，
让三个时段全部不低于独立记录。**第一天跑完拿平台账单再标定一次。**

### 已验证可用的

- `preflight.py` 的文件系统实测跑通了：24 进程 × 20 记录 × {700B, 64KB, 200KB}，

  而不是花掉一个 agent 的整个 session。结论自动写进 `state/fs_facts.md`，
